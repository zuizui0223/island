# Draft pre-submission inquiry — Ecology Letters data policy

**To:** Ecology Letters Editorial Office  
**Subject:** Pre-submission question on third-party trait-data archiving

Dear Ecology Letters Editorial Office,

We are preparing a Letter that combines a global island plant-trait database with independent pollen-supplementation data to test whether floral responses to geographic isolation are reducible to a serial selfing syndrome.

Before submission, we would like to confirm whether our data-archiving plan can meet the journal's Data and Code Availability requirements.

The analyses use a frozen species × trait ledger assembled from multiple published and public third-party sources. We can publicly archive the complete analysis code, corrected geography, derived model-ready outputs, metadata, provenance/rights manifests, and all trait cells for which redistribution is authorized. However, a substantial subset of source-backed trait cells currently carries third-party redistribution restrictions or unresolved reuse terms, so we cannot lawfully redistribute the complete frozen ledger as a new public dataset without additional permissions.

We can provide source-level provenance for every analysis cell, an immutable SHA-256 identity for the full ledger, reconstruction code where source licences permit automated retrieval, and private reviewer access to any material we are legally permitted to share. We will not describe the rights-filtered public subset as the complete analysis database.

Would Ecology Letters consider this situation under its data-availability exception process, and if so, what minimum reviewer-access or reconstruction package would the editors/data editor require at initial submission?

We are asking before submission so that we do not enter review with an archive that falls short of the journal's reproducibility requirements.

Thank you for your guidance.
